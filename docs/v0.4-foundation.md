# Sunbird v0.4 Common Foundation

**Status:** experimental foundation on `v0.4-next`.

This pass implements the state-lifetime concepts shared by both planned v0.4 gameplay directions:

- the primary party/JRPG-oriented line;
- the future `v0.4-solo` action-RPG line.

It intentionally does not add a new effect system, Raylib, realtime scheduling, inventory, or further genre-specific gameplay.

## Canonical state vocabulary

```text
Session
  persistent game lifetime

ActorState
  persistent state of one stable actor

Party
  optional roster/leader policy

ActorBindings
  loaded-area mapping from stable actor key to InstanceId

Level
  immutable authored area definition

AreaState
  mutable instantiated state of one Level

InstanceId
  local runtime identity
```

The old `World` term is no longer canonical. `Sunbird::World` remains a temporary alias of `Sunbird::AreaState` so the v0.3 test corpus and older experimental code can migrate incrementally.

Likewise, `world_view` remains a temporary alias for the canonical `area_view`.

## Persistent actor state

`ActorState` owns persistent values that should survive unloading and re-instantiating an area:

```text
ActorState
├── Vitals
│   ├── hp
│   ├── max_hp
│   ├── mp
│   └── max_mp
└── Stats
    └── attack
```

`Session` owns actor states by stable key:

```text
Session
└── actors
    ├── :hero -> ActorState
    └── :mage -> ActorState
```

Party is optional at the Session level. The current JRPG-oriented App supplies one; a solo branch can construct a Session with a single persistent actor and no Party object.

## Local area state

`AreaState` owns the instantiated state whose lifetime belongs to one loaded Level:

```text
AreaState
├── InstanceIds
├── Position
├── Facing
├── Collision
├── Renderable
├── local Health
├── local Combatant
├── Behavior
└── runtime Relations
```

The player representation in the current prototype therefore has Position/Facing/Collision/Renderable locally, but no local Health or Combatant.

Enemy goblins remain fully local actors and keep local Health and Combatant.

## Explicit actor bindings

The previous Exploration implementation stored a private party-key-to-instance hash.

v0.4 introduces `ActorBindings` as the explicit loaded-area bridge:

```text
stable actor key        local runtime identity
      :hero       --->      InstanceId 0
```

Bindings are intentionally not stored in Session. They belong to the lifetime of the loaded area/mode.

## Battle boundary after this pass

Player attack power now comes from persistent `ActorState::Stats`, not the local player instance:

```text
Session ActorState(:hero).stats.attack
                 |
                 v
             BattleMode
                 |
                 v
        local Attack command
                 |
                 v
             Resolver
                 |
                 v
        enemy AreaState::Health
```

Enemy retaliation still routes through `Session#damage_actor`.

This means the common foundation has clean state ownership, but BattleMode still coordinates two mutation authorities. That is deliberate: the next v0.4 architectural experiment can evaluate Intent/Effect resolution from a clearer baseline.

## Compatibility bridge

Temporary compatibility exists only to avoid coupling the state-model migration to unrelated cleanup:

```text
Sunbird::World       -> Sunbird::AreaState
world_view           -> area_view
Session::Vitals      -> ActorState::Vitals
Session#damage       -> Session#damage_actor
Session#heal         -> Session#heal_actor
Session#spend_mp     -> Session#spend_actor_mp
Session#restore_mp   -> Session#restore_actor_mp
```

New v0.4 code should use the canonical names.

The compatibility layer can be removed after both v0.4 gameplay lines have migrated.

## Genre split

The shared foundation stops below gameplay policy.

Primary/JRPG line may retain:

```text
Party
ExplorationMode
DialogueMode
BattleMode
turn-oriented policy
```

The future `v0.4-solo` line can omit Party and separate BattleMode entirely:

```text
Session
└── :player ActorState

PlayMode
direct combat
weapons/spells
realtime scheduling later
```

Both lines share Level, AreaState, ActorState, ActorBindings, Scene, Host, and the general command/effect research boundary.

## Deliberately deferred

- final removal of the World compatibility alias;
- redesign of Level entry points;
- general Intent -> Rules -> Effects pipeline;
- persistent inventory/equipment;
- persistent world/area changes;
- save serialization;
- Raylib;
- realtime scheduler;
- Lua.
